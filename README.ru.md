# podkop-engine-installer

Установщик [podkop-engine](https://github.com/podkop-net/podkop-engine) для OpenWrt с настроенным [podkop](https://github.com/itdoginfo/podkop).

podkop-engine — сборка sing-box с патчами для podkop. Скрипт ставит её вместо `sing-box` / `sing-box-tiny` и обновляет podkop. Настройки podkop (`/etc/config/podkop`) не меняются.

## Возможности podkop-engine

- **XHTTP:** ссылки `vless://…type=xhttp` в podkop.
- **Резервные ссылки в URLTest:** используются, когда не отвечает ни один основной узел.
- **Проверка узла скачиванием:** перед переключением на узел через него скачиваются 64 КиБ.
- **Fallback на DNS провайдера:** при отказе DNS-сервера, доступного напрямую через WAN.
- **Защита от падений (failsafe):** если sing-box падает циклически, podkop останавливается, чтобы DNS в сети продолжал работать.
- **Лимит памяти Go** подстраивается под доступную память роутера.

Подробности — в [релизах podkop-engine](https://github.com/podkop-net/podkop-engine/releases).

## Требования

| | |
|---|---|
| OpenWrt | 24.10 (`opkg`) или 25.12 (`apk`); менеджер пакетов определяется автоматически. Снапшоты не проверялись |
| Архитектура | `aarch64_cortex-a53`; проверяется по `apk --print-arch`, `/etc/apk/arch` и `DISTRIB_ARCH` |
| podkop | 0.7.0 или новее, установлен и настроен |
| Память | свободно ≥ 50 МБ с учётом памяти, которую занимает текущий sing-box |
| `/tmp` | ≥ 25 МБ свободно |
| Флеш | место под пакет podkop-engine (~22 МБ) за вычетом размера текущего бинарника sing-box |
| Конфликты | `https-dns-proxy` должен быть удалён (конфликтует с podkop) |

Проверено на Xiaomi AX3000T (OpenWrt 24.10, 25.12) и Cudy WR3000S v1 (25.12).

## Версии

По умолчанию скрипт ставит **последние релизы** podkop-engine и podkop с GitHub. Пакеты сверяются по SHA-256, который GitHub публикует для файлов релиза.

В скрипт зашиты проверенные версии. Они используются с ключом `--pinned` и автоматически, если GitHub API недоступен:

| Пакет | Проверенная версия |
|---|---|
| podkop-engine | 1.14.2-r14 |
| podkop, luci-app-podkop, luci-i18n-podkop-ru | 0.7.24 |

Скрипт только обновляет: если установленные podkop или podkop-engine новее целевых, они не трогаются. Если обе версии актуальны, установка не выполняется.

## Использование

```sh
wget -O /root/pe.sh https://raw.githubusercontent.com/markiitwo/podkop-engine-installer/main/install.sh
sh /root/pe.sh check
sh /root/pe.sh
```

При запуске скрипт предлагает выбрать язык интерфейса (English / Русский, стрелки и Enter; по умолчанию English). На вопросы отвечают `y` / `n`.

| Команда | Действие |
|---|---|
| `sh pe.sh` | Установка или обновление. Перед началом выводит план и запрашивает подтверждение |
| `sh pe.sh check` | Только проверка требований, без изменений |
| `sh pe.sh rollback` | Возврат обычного sing-box вместо podkop-engine |
| `sh pe.sh report` | Отчёт для диагностики, см. [Отчёт](#отчёт) |
| `sh pe.sh help` | Справка |

| Ключ | Действие |
|---|---|
| `-y`, `--yes` | Без вопросов: берутся ответы по умолчанию |
| `--pinned` | Ставить проверенные версии вместо последних релизов |
| `--no-rollback` | Не откатывать автоматически, если проверка после установки не прошла |
| `--lang en\|ru` | Язык интерфейса без меню выбора |

Для `install` и `rollback` нужен интерактивный терминал; без него скрипт завершается, если не указан `-y`.

Во время установки podkop останавливается примерно на 1–2 минуты. Обрыв SSH-сессии установку не прерывает.

## Порядок работы

1. **Проверка:** версия OpenWrt и менеджер пакетов, архитектура, версия podkop, наличие прокси-секций, целевые версии, память, флеш, `/tmp`, DNS, текущая работоспособность прокси.
2. **Подготовка, пока podkop ещё работает:**
   - если не хватает зависимостей podkop (`curl jq kmod-nft-tproxy coreutils-base64 bind-dig ca-bundle`) — обновление списков пакетов и установка недостающего;
   - скачивание пакетов podkop-engine и podkop со сверкой SHA-256;
   - сохранение копии текущего пакета sing-box для отката; если скачать её не удалось — копия текущих файлов sing-box в оперативной памяти для автоотката в этом же запуске.
3. **Резервная копия:** `/etc/config/podkop`, `/etc/config/sing-box`, `/etc/config/dhcp`, `/etc/sing-box`, а на 25.12 ещё и `/etc/apk/world` — в архив.
4. **Установка:**
   - `opkg`: удаление старого пакета sing-box (`--force-depends`), затем установка podkop-engine;
   - `apk`: из `/etc/apk/world` удаляются записи `sing-box`, `sing-box-tiny`, `!podkop-engine`, затем установка одной транзакцией.

   Затем обновляются podkop и LuCI, автозапуск `sing-box` отключается (его запускает podkop), включается служба `podkop-engine` (failsafe), podkop запускается.
5. **Проверка результата (до 2 минут):**
   - процесс sing-box запущен;
   - `fakeip.podkop.fyi` резолвится в диапазон FakeIP;
   - обычный DNS работает;
   - запрос через mixed-вход podkop (`127.0.0.1:4534`) возвращает 204 — если прокси работал до установки.

   Если хоть одна проверка не прошла, а также при Ctrl+C во время установки — автоматический откат.

## Сетевое поведение

- **Тайм-аут:** у каждой сетевой операции `apk`/`opkg` — 90 с.
- **Порядок попыток для списков пакетов и установки из репозитория:**
  1. `downloads.openwrt.org`;
  2. зеркало `mirrors.cicku.me/openwrt` (фиды переключаются временно и сразу восстанавливаются, в том числе при ошибке и Ctrl+C);
  3. HTTP-прокси podkop.

  Подписи пакетов при этом проверяет сам `apk` / `opkg`.
- **Копия sing-box для отката** скачивается только с `downloads.openwrt.org` (напрямую или через прокси podkop), но не с зеркала: при откате она ставится из локального файла без проверки подписи.
- **GitHub** (API и пакеты): через прокси podkop, если он работает, иначе напрямую; при отсутствии `curl` используется `wget`.

## Откат

`sh pe.sh rollback`:
1. останавливает podkop — DNS и интернет продолжают работать без прокси;
2. ставит сохранённый пакет sing-box, а если его нет — `sing-box-tiny` из репозитория; во время установки последний резерв — копия файлов sing-box в оперативной памяти;
3. восстанавливает `/etc/config/sing-box` и запускает podkop.

podkop остаётся на установленной версии: он совместим и с обычным sing-box.

## Отчёт

`sh pe.sh report` собирает:
- модель, версии OpenWrt, podkop и sing-box;
- память и флеш;
- состояние служб и открытые порты;
- проверки DNS и прокси;
- `uci show podkop` и `uci show sing-box`, параметры dnsmasq;
- журнал podkop и sing-box;
- `podkop global_check`;
- хвост журнала установки.

Из отчёта удаляются ссылки на прокси, `outbound_json`, UUID, пароли, ключи и short ID. Остаются внешний IP и доменные имена из журналов.

## Ограничения

- Из коробки поддерживается только `aarch64_cortex-a53`. С `ENGINE_ARCH=<arch>` скрипт ищет пакеты другой архитектуры в последних релизах; встроенные контрольные суммы есть только для `aarch64_cortex-a53`, поэтому `--pinned` и офлайн-фолбэк для других архитектур не работают.
- Ставится вариант `podkop-engine` (протоколы, которые использует podkop), не `podkop-engine-full`.
- Скрипт не настраивает podkop и не проверяет работоспособность конкретных прокси-серверов.
